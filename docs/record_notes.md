# Record notes

Personal study notes: what each finished stage does and the concepts behind it.
Status lives in `ROADMAP.md`, design in `architecture.md`. Last updated: 2026-11-08

**RAG** = retrieve relevant text from your own documents first, then make the LLM answer only from it. Less hallucination, verifiable answers.

## 1. Ingestion
PDFs → pages → chunks → embeddings → Chroma.
- **Chunking (1000 chars, 200 overlap):** one idea per chunk keeps retrieval precise; overlap stops a sentence cut at a boundary from being lost.
- **Embedding** (`text-embedding-3-small`): text → vector; similar meaning = nearby vectors.
- **ChromaDB:** embedded vector database on disk, cosine distance.
- **Chunk id** `<file>::p<page>::c<index>` is deterministic, so re-ingest overwrites. Changed chunk settings leave old ids behind: delete the collection first.

## 2. Hybrid retrieval
Cheap wide net first (recall), expensive precise step last (precision).
- **Vector search:** matches meaning ("how much exercise" finds "150 minutes of activity"); weak on exact terms, numbers, acronyms.
- **BM25:** keyword ranking from term frequency, rarity of the term across the corpus (IDF) and length normalisation; strong on exact words, blind to synonyms.
- **Hybrid:** each fails where the other works, so run both (20 candidates each).
- **RRF:** merge by rank, not score: `Σ 1/(k + rank)`, k=60. BM25 scores and cosine distances are not comparable.
- **Cohere rerank:** a cross-encoder reads query and chunk together, so it is more accurate than comparing vectors but too slow for everything. Runs on the shortlist only.
- **Fallback:** Cohere failure keeps RRF order, logs a warning, sets `reranked=false`.

## 3. Generation with citations
- Chunks are labelled `[Source N]` in the prompt; `gpt-4o-mini` at temperature 0 (low variance, not deterministic: average eval runs).
- Prompt lives in versioned YAML, never in Python.
- `validate_citation`: N must be in range, else the citation is fabricated. It does **not** check that the source supports the claim.
- Gotchas: `[Source 1-3]` parses as {1, 3}; `citation_accuracy` is 0.0 for refusals, so filter on `has_citations`.

## 4. Query logging and `/history`
- `query_logs` stores answer, citation counts and a retrieval trace (ids, rerank scores, prompt/model versions, latency): lets you explain a bad answer later.
- `/history`: one aggregate query with `FILTER (WHERE ...)`, plus recent and fabricated-citation lists.
- A database failure never fails `/query`. Routes stay thin; SQL lives in `db.py`.
- Postgres `avg()` returns `Decimal`, `sum()` of no rows is NULL: convert in Python.

## 5. Schema and Alembic
- Alembic version-controls the schema (`upgrade` / `downgrade`); `alembic check` compares models to database.
- Never `create_all` on Postgres. Read every autogenerated migration. Prove it with upgrade → check → downgrade → upgrade.
- `JsonType` = JSONB on Postgres, JSON on SQLite (offline tests).
- `eval_runs` / `eval_results` are separate so eval traffic does not skew `/history`. Fabricated count is derived (`total − valid`), not stored.

## 6. Housekeeping
- Leaked key revoked and purged from git history; `.env` ignored, `.env.example` is the template.
- Hand-written `requirements*.txt`; `langchain-community<0.4` pinned so ragas imports.
- One branch per task, Conventional Commits, squash-merge, phase tags.
- Ruff (linter) auto-fixes: import order (isort rules), `datetime.UTC`, `X | Y` instead of `Union`, stale `noqa` comments.

## 7. Offline unit tests
Goal: prove our logic is right in seconds, with no network, no cost, no real database. These run in CI on every PR.
- **Unit test:** one function checked in isolation. The vendors (OpenAI, Cohere, Postgres) are replaced by fakes, so a test checks *our decision*, not their API.
- **Env before import:** `conftest.py` sets dummy keys and a temp `CHROMA_PATH` before `app` is imported, because settings and API clients are built at import time. Assigned, not `setdefault`, so a real `.env` key can never leak in. A guard test fails if the dummy values are not active.
- **Monkeypatch:** swaps a function for a fake for one test, then restores it. Used to fake `vector_search`, `bm25_search` and `cohere_client.rerank`, so `retrieve()` runs end to end offline.
- **Testing the fallback:** the fake Cohere raises `ApiError`; the test asserts RRF order comes back, no `rerank_score`, and a warning is logged.
- **SQLite instead of Postgres:** `JsonType` lets the same models run on SQLite. `StaticPool` is needed: an in-memory SQLite database exists per connection, so without it each connection sees empty tables. Limit: SQLite `avg()` returns float, so the Postgres `Decimal` gotcha and JSONB are not covered offline.
- **`xfail(strict=True)`:** documents a known bug as a test. Suite stays green while the bug exists, then fails loudly when someone fixes it, telling you to delete the marker. Used for `[Source 1-3]` parsing as {1, 3}.
- **Mutation check:** break the code on purpose (RRF `1/(k+rank)` → `1/rank`) and confirm tests fail. Proves the tests can actually catch a regression.
- Invariants now pinned: Cohere failure degrades to RRF order; a logging failure never fails `/query`; refusals score 0.0 and drag down only the all-rows mean.
- Gotcha: the report key is `has_citation`, the DB column is `has_citations`.

## 8. Evaluation
Unit tests prove the code is *correct*; the eval measures whether answers are *good*, on real data, with real (paid) calls.
- **Gold set:** questions you wrote, each labelled with the pages that answer it (page-level, not chunk ids, so labels survive re-chunking). ~20% are unanswerable to test refusals. A short reference answer feeds the RAGAS judge.
- **Page = PDF position**, not the printed page number. PDF extraction also inserts stray spaces ("tr aining"), so `find_pages.py` ignores whitespace.
- **The same fact on many pages:** guideline PDFs repeat recommendations (summary, chapter, annex). If gold lists only one of them, a correct retrieval of another page scores as a miss. List every page that fully states the answer.
- **Retrieval metrics (free):** `hit@k` = any gold page in the top k; **MRR** = 1/rank of the first gold chunk (rewards ranking it high); page recall = share of gold pages found.
- **Answer metrics (free):** citation accuracy (cited numbers exist), `cited_gold` (cited the right page; covers what `validate_citation` cannot), false and correct refusal rates.
- **RAGAS (LLM-as-judge):** faithfulness = share of the answer's claims supported by the retrieved text (hallucination); answer relevancy; context precision = useful chunks ranked first; context recall = retrieved text covers the reference. The judge is also `gpt-4o-mini`, so it may grade its own style kindly.
- **Thresholds as a gate:** the runner exits 1 below a threshold, so it can block a merge. Set them from a baseline of 3 runs (`temperature=0` still varies), a little under the worst run.
- **Baseline (set v1.3, 3 runs):** hit@k 1.00, MRR 0.77, cited_gold 0.97, citation accuracy 1.00, refusals 8/8 correct and 1/32 false, faithfulness ~0.96. Thresholds sit a little under these; `answer_relevancy` is left ungated because it marks good short answers down.
- **What the eval found:** questions comparing both documents can come back with pages from only one (a false refusal on q035), which is a retrieval design gap, not a bug.
- **Comparable runs:** every run stores git sha, config and eval-set version; a run where Cohere fell back to RRF is marked invalid, because the fallback quietly changes ranking.

## 9. Docker + CI
Goal: the same checks run on every PR without anyone remembering to, and the whole service starts with one command.
- **CI (GitHub Actions):** a YAML workflow GitHub runs on a fresh Linux machine for every PR and push to `main`. Ours runs ruff, the Alembic round trip (upgrade → check → downgrade base → upgrade) on a throwaway Postgres, pytest, and a `docker build`. A red check blocks a bad merge.
- **Service container:** CI starts `postgres:17` next to the job, so migrations are proven on a real Postgres, not just SQLite.
- **No secrets in CI:** dummy API keys only; the unit tests never call OpenAI or Cohere. The eval needs paid keys and the PDFs, so it stays local.
- **Image vs container:** the Dockerfile is the recipe, the image is the built result, a container is a running copy. Copying `requirements.txt` before the code means a code change does not reinstall dependencies (layer caching).
- **`.dockerignore`:** keeps `.env`, `.git`, the index and PDFs out of the image, so secrets are never baked in. Keys are passed at run time via `env_file`.
- **Compose:** one file describing several containers (API + Postgres) and their network; the API reaches the database by its service name `db`. `depends_on` with a healthcheck waits until Postgres accepts connections.
- **Bind mount vs named volume:** a bind mount shares a host folder (`./chroma_db`, so no paid re-ingest); a named volume (`pgdata`) is Docker-managed storage that survives restarts.
- **Port gotcha:** the native Postgres owns 5432, so the container is published on 5433. Ports bind to 127.0.0.1 because `/history` and `/ingest` have no auth.
