# Project Name
"Ask My Docs" — production RAG over exercise science and public health guidelines.

## Tech Stack
- Backend: FastAPI, Python 3.12 (conda env `askdocs`)
- Vector store: ChromaDB, embedded on disk at `./chroma_db`
- Retrieval: OpenAI `text-embedding-3-small` + BM25, fused with RRF, reranked by Cohere `rerank-v3.5`
- Generation: OpenAI `gpt-4o-mini`, temperature 0
- Database: PostgreSQL 17 (native Windows service) + SQLAlchemy 2.0 + Alembic
- Eval: RAGAS + custom metrics
- Planned, not built yet: Celery + Redis, Streamlit, Docker Compose, GitHub Actions CI

## Environment
- Always use the `askdocs` conda env. The default `python` and the old `openaitest` env have the wrong packages.
- Before any `pip install`, check: `python -c "import sys; print(sys.prefix)"` must end in `envs\askdocs`.
- Install: `pip install -r requirements-dev.txt`. Runtime deps live in `requirements.txt`; never paste a `pip freeze` into it.
- `langchain-community` is pinned `<0.4` on purpose: every ragas release up to 0.4.3 imports a module removed in 0.4.

## Commands
- Dev server: `uvicorn app.main:app --reload` (API docs at http://127.0.0.1:8000/docs)
- Ingest PDFs: `python -m app.ingest` (calls OpenAI embeddings, costs money)
- Run tests: `pytest`
- Run eval: `python eval/run_eval.py`
- Lint: `ruff check .`
- Migrations: `alembic upgrade head` · new migration: `alembic revision --autogenerate -m "..."` · verify: `alembic check`
- Docker: `docker compose up --build` (planned)

## Architecture
Full design, data flow and schema: `docs/architecture.md`.
- `app/config.py` — all settings (pydantic-settings, `.env`)
- `app/ingest.py` — PDFs → pages → chunks (1000/200) → embeddings → Chroma upsert. Chunk ids: `<file>::p<page>::c<index>`
- `app/retriever.py` — `retrieve()`: vector + BM25 (`candidate_k` each) → `reciprocal_rank_fusion` → Cohere `rerank`; falls back to RRF order if Cohere fails
- `app/generator.py` — `[Source N]` context, `generate_answer`, `validate_citation`
- `app/db.py` — ORM models (`query_logs`, `eval_runs`, `eval_results`), `log_query`, `/history` readers
- `app/main.py` — routes: `/health`, `/query`, `/ingest`, `/history`
- `alembic/` — migrations; `env.py` reads the database URL from settings
- `prompts/` — versioned prompt templates in YAML
- `eval/` — evaluation set + eval runner
- `data/raw/` (source PDFs) and `chroma_db/` (vector index) are not committed

## Conventions
- All config via pydantic-settings, loaded from .env
- Prompts stored in YAML, never hardcoded in Python
- Every retrieval change must pass eval thresholds before merge
- Type hints on all function signatures
- Docstrings on public functions
- Route handlers stay thin: SQL lives in `app/db.py`, pipeline logic in `retriever.py` / `generator.py`
- A database failure must never fail a user request: `/query` catches `SQLAlchemyError` from logging

## Database and migrations
- Schema changes go through Alembic only. Never run `Base.metadata.create_all` against Postgres; that is how the first migration ended up empty.
- Read every autogenerated migration before applying it. An empty `upgrade()` means the database already matched the models.
- Prove each migration with a round trip: `alembic upgrade head` → `alembic check` → `alembic downgrade -1` → `alembic upgrade head`.
- JSON columns use `JsonType` (JSONB on Postgres, JSON on SQLite) so offline tests can run on SQLite.
- The eval runner writes to `eval_runs` / `eval_results` and calls `retrieve()` / `generate_answer()` directly, never `/query`, so `/history` shows only real traffic.

## Testing
- Unit tests run offline: no Postgres, no API calls. `tests/conftest.py` sets dummy keys and a temp `CHROMA_PATH` before importing `app`.
- In-memory SQLite fixtures need `poolclass=StaticPool`; otherwise each connection gets its own empty database.
- Verify offline first, live second. Say so before running anything that spends API credits.

## Known gotchas
- `citation_accuracy` is 0.0 for refusals, not NULL: filter on `has_citations` before averaging.
- `validate_citation` checks only that `[Source N]` is in range, not that the source supports the claim.
- The BM25 index cache is keyed on chunk count and `load_prompt()` is cached: restart the server after re-ingesting or editing the prompt.
- Re-ingesting with new chunk settings leaves old chunk ids in Chroma; delete the collection first.
- Postgres `avg()` returns `Decimal` and `sum()` over no rows returns NULL: convert in Python.

## Git workflow
- Never commit directly to `main`. One branch per task: `feat/`, `fix/`, `refactor/`, `docs/`, `test/`, `ci/`.
- Conventional Commits: `feat:`, `fix:`, `refactor:`, `docs:`, `test:`, `ci:`, `chore:`. One logical change per commit.
- Branch from an up-to-date `main` (`git switch main && git pull`). Merge PRs with "Squash and merge", then delete the branch.
- When unrelated changes are pending, commit only the listed paths: `git commit -m "..." -- <paths>`.
- Don't commit or push unless asked. Never force-push, `git reset --hard`, or use `--no-verify` without asking.
- Before a PR: `ruff check .`, `pytest`, and the eval if retrieval, prompts, or eval code changed. Put eval scores in the PR description.

## Off-limits
- Never modify .env directly — use .env.example as the template
- Never commit API keys or secrets
- Don't change eval thresholds without explicit instruction
